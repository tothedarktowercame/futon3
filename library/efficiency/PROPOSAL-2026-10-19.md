# Proposal: `efficiency` pattern set (claude-5 with claude-14, 2026-10-19)

Commissioned by Joe, 2026-10-19 ~13:45Z: "create a new futon3/library/efficiency
pattern set; claude-14 has been making lean blueprints with a similar character".

Two programs this week reached the same shape from different material:

- **WM wiring repairs** (codex-1, futon2 `fad572386`): an audit of 11 correlation
  rows became 34 one-turn packets, each with files, a bad-case test and a
  serving-JVM probe, dependency-ordered, with a coverage ledger and a "cannot be
  one turn" section. 128 commits landed in one morning. Before this, the same
  faults were found one click at a time.
- **Lean blueprints** (claude-14, apm-lean `holes/labs/blueprints/`): a 300-600
  line proof boundary becomes ~15 leaves of 30-150 lines, each a top-level lemma
  closed by one `sorry`, true as stated, proved by separate seats within hours.
  The foundation ranking orders the shared lemmas by how many problems each one
  closes.

Both replace serial discovery with a reviewed decomposition that many seats
consume in parallel. That is the subject of the set. The gain is throughput, so
the set is `efficiency`, with the understanding that the efficiency comes from
the review step, not from skipping it.

## Candidate patterns (draft, for claude-14's redline)

Each is written from one side; the other side's evidence is named so the
flexiarg can cite both. Names are provisional.

1. **split-by-shared-dependency** (claude-14's review note). Split by the fact two
   pieces would both have to prove, not by conclusion; otherwise two seats prove
   it twice and the "parallel" layer is serial. WM side: P03 is the shared reader
   that P04, P14 and P33 all depend on, stated once.
2. **give-the-dependent-piece-its-hypothesis** (preamble rule). Where B needs A's
   conclusion, B takes it as an explicit hypothesis, so B is provable before A
   lands; the checker rejects a lemma whose axioms include another's sorry. WM
   side: packets name `depends P03` and are otherwise self-contained; "scope
   cannot expand because a later consumer refuses".
3. **seat-sized-units** (both). 30-150 lines of proof; one turn, one behaviour,
   one bad-case test. Symptom of too big: "and" between two nouns in the goal; a
   piece that silently carries the whole argument. Symptom of too small: a leaf
   that restates its hypothesis, or a packet that only renames.
4. **no-placeholder-leaves** (claude-14, 2026-10-15). Never a `True` lemma to mark
   a step; a leaf states the claim the assembly consumes. WM side: never
   manufacture a zero, posterior, witness or successful execution to fill an
   absent field.
5. **the-assembly-does-not-move** (both). Main theorem and its definitions stay
   byte-identical while leaves are proved; the registered statement check still
   passes. WM side: packet IDs P01-P33 kept when P00 was inserted; the frontier
   envelope every packet preserves.
6. **review-the-decomposition-before-dispatch** (both). Blueprint reviewed for
   truth of each lemma, theorem identical, compiles, axioms, *then* queued; m98J02
   was rejected at this step because a lemma was false. WM side: packet premises
   spot-checked against current source before the first dispatch; the review
   itself found the Q2 guard that P00 now covers.
7. **cover-every-row-or-say-why-not** (WM coverage ledger). Every source row gets
   a unit or a stated reason it needs none; already-landed rows are listed so they
   are not dispatched again. Lean side: m97A06 found already sorry-free, recorded,
   not copied.
8. **order-by-what-it-unlocks** (foundation ranking). Rank shared pieces by how
   many consumers they close, widest first; single-consumer closures wait. WM
   side: P00-P03 first because they sit before every other packet's consumer.
9. **name-the-piece-that-is-not-one-turn** (both). A large missing foundation is
   marked LIBRARY and the rest stays small; a WM plan has a "cannot be one turn"
   section that names the split rather than hiding the size inside a packet.
10. **fresh-thread-per-unit** (bp-next.sh). Reset the seat's session before each
    unit; a long-lived thread overflows. Queue serially with parks whose deadline
    exceeds the queue wait, and check state before re-dispatching.
11. **author-is-not-reviewer-at-the-leaf** (open question). Blueprints are
    reviewed by claude-14 before and after seats prove them. codex-1 wrote and
    reviewed its own packets; the five live clicks are the independent check.
    Is this an efficiency pattern or an apparatus one? claude-14 to say.

## Not in this set

Patterns about the apparatus judging faults (apparatus/), about pattern form
(pattern-discipline/), or about proof tactics (math-strategy/). The set is about
decomposing work for parallel seats and the review that makes that safe.
